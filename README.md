# Wish list

Адаптивный лендинг с вишлистом для GitHub Pages. Название, изображение, описание и любое количество ссылок на магазины для каждой вещи. Если магазинов несколько, ссылки собраны в раскрывающийся список «Где купить»; для одного магазина отображается прямая ссылка. Есть поиск и фильтры по категориям. Серверная часть и база данных не нужны.

## Локальный запуск

Нужен Node.js 22 или новее.

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Используйте HTTP-сервер: загрузка JSON через `fetch` не работает при открытии HTML как `file://`.

```sh
npm run check  # проверить карточки и локальные изображения
npm run build  # проверить данные и собрать сайт в dist/
```

## Проверка кода и форматирование

```sh
npm run lint          # ESLint: браузерный JS и скрипты Node.js
npm run lint:fix      # автоматическое исправление замечаний ESLint
npm run format       # форматирование файлов через Prettier
npm run format:check # проверка форматирования без изменений
```

Конфигурации: `eslint.config.js`, `.prettierrc.json` и `.prettierignore`. Папки `dist/` и `node_modules/` исключены из проверок. GitHub Actions устанавливает зависимости через `npm ci` и проверяет код и форматирование перед сборкой и публикацией.

## Как обновить желания

Отредактируйте `data/wishlist.json`, затем закоммитьте изменения и отправьте их в `main` или `master`. GitHub Actions соберёт и обновит сайт.

Пример файла с одной карточкой:

```json
{
  "intro": "Вещи, которым я буду рад.",
  "items": [
    {
      "id": "my-gift",
      "title": "Название желания",
      "description": "Например, нужный цвет или размер",
      "category": "Для дома",
      "image": "./assets/my-gift.jpg",
      "favorite": true,
      "shops": [
        { "name": "Название магазина", "url": "https://example.com/product" },
        { "name": "Другой магазин", "url": "https://example.org/product" }
      ]
    }
  ]
}
```

- Обязательные поля карточки: уникальный `id`, `title`, `image`, непустой список `shops`. У магазина обязательны `name` и `url`.
- Изображения кладите в `assets/` и указывайте путь `./assets/имя-файла.jpg`. Можно указать и полный HTTPS-адрес; локальные изображения не зависят от доступности сторонних сайтов. При ошибке загрузки появится заглушка.
- `description`, `category` и `favorite` необязательны. Категории появляются автоматически; карточки идут в порядке массива `items`.
- Необязательное поле `title` на верхнем уровне меняет большой заголовок, `intro` — вводный текст.
- Чтобы убрать полученный подарок, удалите его объект из `items` и сделайте коммит. Бронирования и состояния на сервере нет.

Сборка проверяет структуру данных, обязательные поля, уникальность ID, протоколы ссылок и наличие локальных изображений. Ошибка останавливает публикацию, оставляя предыдущую версию сайта.

## Публикация в GitHub Pages

1. Загрузите проект в репозиторий GitHub, в ветку `main` или `master`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. Откройте **Actions → Deploy wishlist to GitHub Pages** и запустите workflow вручную либо отправьте следующий коммит.
4. После успешного запуска ссылка появится в **Settings → Pages** и в environment `github-pages`.

Workflow находится в `.github/workflows/pages.yml`. Если используется другая ветка, измените `on.push.branches`. В артефакт публикации входят только `dist/` с готовым сайтом. Все пути относительные: сайт поддерживает и `username.github.io`, и `username.github.io/repository/` без изменения конфигурации.

Настройка своего домена при необходимости выполняется отдельно в Settings → Pages.

Справка: [GitHub — публикация через собственный workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Оформление

Основные цвета и стили находятся в `styles.css`, разметка — в `index.html`. Светлая и тёмная темы следуют системной настройке до ручного переключения кнопкой в шапке. Выбор темы сохраняется в `localStorage`; при недоступности хранилища переключение работает до перезагрузки страницы. Логика темы находится в `theme.js`, палитры — в CSS-переменных.

Фотографии товаров лежат локально в `assets/`, источники указаны в `assets/SOURCES.md`. Изображения вписываются в область карточки целиком без обрезки. Шрифт Manrope загружается из Google Fonts; при недоступности используется Arial. Кроме выбранной темы, данные посетителей не сохраняются.
